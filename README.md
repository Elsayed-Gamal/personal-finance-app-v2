# Personal Finance App

تطبيق ويب متكامل لإدارة المال الشخصي من مكان واحد. يتيح للمستخدم متابعة الرصيد والمعاملات، تنظيم الميزانيات الشهرية، الادخار عبر أهداف مالية (Pots)، ومراجعة الفواتير المتكررة من خلال واجهة سريعة ومتجاوبة.

هذا المشروع نسخة نهائية مخصّصة للعرض في البورتفوليو، وتوضح بناء تطبيق مالي يعتمد على المصادقة، عزل بيانات المستخدمين، وعمليات مالية آمنة على مستوى قاعدة البيانات.

## أبرز المزايا

- لوحة Overview تلخّص الرصيد والدخل والمصروفات والميزانيات والمدخرات.
- إدارة المعاملات مع البحث والتصفية والترتيب وتقسيم النتائج إلى صفحات.
- إنشاء الميزانيات وتعديلها وحذفها، مع متابعة الإنفاق حسب التصنيف والشهر.
- إنشاء أهداف ادخار وإيداع الأموال فيها أو سحبها منها.
- متابعة الفواتير المتكررة وحالات الدفع والاستحقاق القريب.
- تسجيل الحسابات وتسجيل الدخول باستخدام Credentials وجلسات JWT.
- صفحة Profile لتحديث الاسم وكلمة المرور وتعيين الرصيد الافتتاحي.
- لوحة Admin لإدارة المستخدمين والتحكم في إتاحة التسجيل.
- تصميم متجاوب مع رسوم بيانية وانتقالات حركية.

## لمحات تقنية

- يعتمد التطبيق على **Next.js App Router** مع Server Components للعرض وServer Actions لعمليات التعديل.
- تُفحص المدخلات باستخدام **Zod**، وتُشفّر كلمات المرور باستخدام **bcryptjs**.
- تُربط البيانات المالية بالمستخدم المسجّل، مع فحوص ملكية على الخادم.
- تُنفّذ تغييرات المعاملات والتحويلات الخاصة بأهداف الادخار عبر PostgreSQL RPCs ذرية للمحافظة على اتساق الرصيد.
- توجد اختبارات وحدات واختبارات قاعدة بيانات لعزل الحسابات والصلاحيات والعمليات المالية.

## التشغيل محليًا

### المتطلبات

- Node.js 22.12 أو أحدث
- npm
- مشروع Supabase بقاعدة البيانات المطلوبة

### الإعداد

1. ثبّت الاعتماديات:

   ```bash
   npm install
   ```

2. أنشئ ملف `.env.local` في جذر المشروع:

   ```env
   SUPABASE_URL=https://your-project.supabase.co
   SUPABASE_KEY=your-server-side-supabase-key
   AUTH_SECRET=replace-with-a-long-random-secret
   ```

   يجب أن يبقى `SUPABASE_KEY` مفتاحًا سريًا خاصًا بالخادم، وألا يُستخدم داخل كود العميل أو يُضاف إلى Git.

3. جهّز قاعدة البيانات بتطبيق ملفات `supabase/migrations` بالترتيب. هذه الملفات مصممة لترقية مخطط المشروع، وليست مخططًا كاملًا لإنشاء قاعدة جديدة من الصفر. يشرح [دليل عزل البيانات](docs/data-isolation.md) نموذج الوصول وتفاصيل الترحيل.

4. شغّل خادم التطوير:

   ```bash
   npm run dev
   ```

5. افتح [http://localhost:3000](http://localhost:3000).

## أوامر المشروع

```bash
npm run dev      # تشغيل بيئة التطوير
npm run build    # إنشاء نسخة الإنتاج
npm run start    # تشغيل نسخة الإنتاج
npm run lint     # فحص جودة الكود
npm test         # تشغيل اختبارات الوحدات والخدمات
npm run test:db  # تشغيل اختبارات PostgreSQL المحلية
```

يتطلب `npm run test:db` وجود PostgreSQL 16 أو أحدث محليًا. ينشئ الأمر قاعدة مؤقتة مستقلة، ولا يتصل بمشروع Supabase أو يقرأ `.env.local`.

## بنية المشروع

```text
app/
  (auth)/        صفحات تسجيل الدخول وإنشاء الحساب
  (main)/        صفحات التطبيق المحمية
  _actions/      Server Actions
  _features/     مكونات كل نطاق وظيفي
  _services/     المصادقة والوصول إلى البيانات
  _UI/           مكونات الواجهة المشتركة
  _utils/        التحقق من البيانات والدوال المساعدة
  api/           Route Handlers
supabase/
  migrations/    ترحيلات قاعدة البيانات والدوال المالية
tests/            اختبارات التطبيق وقاعدة البيانات
proxy.js          حماية المسارات وإعادة التوجيه
```

## نطاق النسخة

المشروع مخصص للعرض التقني في البورتفوليو، وليس منتجًا مصرفيًا أو نظامًا محاسبيًا معتمدًا. صفحة الفواتير المتكررة مخصصة للعرض والمتابعة فقط، ولا تنفّذ مدفوعات حقيقية. قبل استخدام المشروع مع بيانات فعلية يجب تطبيق جميع migrations، حماية أسرار الخادم، ومراجعة سياسات RLS والصلاحيات في بيئة Supabase المستهدفة.
