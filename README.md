# Personal Finance App

تطبيق لإدارة المال الشخصي مبني باستخدام Next.js وSupabase. يوفّر المشروع واجهة لإدارة المعاملات والميزانيات والـ Pots والفواتير المتكررة، بالإضافة إلى المصادقة وإدارة المستخدمين من خلال لوحة Admin.

> **حالة المشروع:** نسخة MVP قيد التطوير. تم تنفيذ عزل البيانات وعمليات الـ Pots الذرية واختبارها محليًا. تم تطبيق `mutate_owned_transaction` و`mutate_owned_pot` و`get_owned_overview_summary` ودوال التقارير وتهيئة الرصيد الافتتاحي على Supabase بتاريخ 19 أكتوبر 2026؛ migrations العزل وقيود الميزانيات ما زالت معلّقة؛ يجب اتباع [دليل الترحيل](docs/data-isolation.md) قبل تشغيل النسخة الجديدة على البيانات الفعلية. خطة إكمال الموقع في [خطة التسليم](docs/delivery-plan.md).

## المزايا الحالية

- تسجيل الدخول والتسجيل باستخدام NextAuth Credentials و`bcryptjs`.
- التحقق من المدخلات باستخدام Zod.
- عرض المعاملات مع البحث والترتيب والتصفية حسب التصنيف وPagination.
- عرض الميزانيات وحساب المصروف حسب التصنيف.
- إنشاء وتعديل وحذف Pots وإضافة الأموال وسحبها.
- عرض الفواتير المتكررة.
- تحديث اسم المستخدم وكلمة المرور.
- لوحة إدارة للمستخدمين تشمل الإنشاء والتعديل والحذف وتغيير حالة التسجيل.
- واجهة مبنية باستخدام Tailwind CSS وRecharts وMotion.

## التشغيل المحلي

1. ثبّت الاعتماديات:

   ```bash
   npm install
   ```

2. أنشئ ملف `.env.local` في جذر المشروع:

   ```env
   SUPABASE_URL=https://your-project.supabase.co
   SUPABASE_KEY=your-server-side-supabase-key
   AUTH_SECRET=replace-with-a-long-random-secret
   ```

   يستخدم التطبيق حاليًا `SUPABASE_URL` و`SUPABASE_KEY` مباشرة في [app/\_services/supabase.js](app/_services/supabase.js). يجب عدم نشر مفتاح Supabase ذي الصلاحيات المرتفعة أو وضعه داخل كود العميل.

3. شغّل بيئة التطوير:

   ```bash
   npm run dev
   ```

4. افتح [http://localhost:3000](http://localhost:3000).

## أوامر المشروع

```bash
npm run dev      # تشغيل بيئة التطوير
npm run lint     # فحص ESLint
npm run build    # إنشاء نسخة الإنتاج
npm run start    # تشغيل نسخة الإنتاج بعد build
npm test         # اختبارات الخدمات والصلاحيات
npm run test:db  # اختبارات SQL على PostgreSQL محلي مؤقت
```

اختبارات قاعدة البيانات تحتاج PostgreSQL محليًا؛ لا تتصل بمشروع Supabase ولا تقرأ `.env.local`. تفاصيل التشغيل والتغطية في [دليل العزل](docs/data-isolation.md).

## إعداد قاعدة البيانات

يعتمد التطبيق على الجداول وView التالية في Supabase:

- `users`
- `transactions`
- `categories`
- `budgets`
- `pots`
- `themes`
- `settings`
- `balance_snapshots`
- `unique_recurring_bills` كـ View للفواتير المتكررة

يجب أن تحتوي `users` على الأقل على الحقول المستخدمة في التطبيق:

- `id`
- `name`
- `email`
- `password`
- `role` بقيمة `USER` أو `ADMIN`
- `created_at`

توجد migrations لتحديث قاعدة البيانات الحالية في `supabase/migrations`. ملف `tests/database/legacy-schema.sql` نموذج للاختبار فقط، وليس seed للإنتاج أو مخططًا معتمدًا لإنشاء مشروع جديد. جميع الخدمات المالية تستخدم جلسة NextAuth وفلتر المستخدم؛ مفتاح Supabase السري محصور في السيرفر.

## بنية المشروع

```text
app/
  (auth)/             صفحات تسجيل الدخول والتسجيل
  (main)/             صفحات التطبيق الرئيسية
  _actions/           Server Actions لتعديل البيانات
  _contexts/          React Contexts
  _features/          مكونات كل نطاق وظيفي
  _services/          طبقة الوصول إلى Supabase والمصادقة

  _utils/             أدوات التحقق والمساعدات

```

## ملاحظات مهمة قبل الإنتاج

هذه النقاط ما زالت مطلوبة:

1. تطبيق migrations واختبار النسخة المتكاملة، مع الحفاظ على الأرصدة التاريخية وعدم تهيئة الحسابات القديمة تلقائيًا.
2. واجهات المعاملات والميزانيات وملخص Overview أصبحت منفذة محليًا، والميزانيات تدعم اختيار الشهر. يلزم تطبيق migrations المعلقة والتحقق في المتصفح. تم تأجيل العمل على الفواتير بطلب المستخدم؛ الصفحة الحالية ما زالت تحتوي ملخصًا تجريبيًا.
3. استكمال تجربة الموبايل وإمكانية الوصول واختبارات المتصفح.
4. فحص حزم التشغيل بتاريخ 19 أكتوبر 2026 رجّع صفر ثغرات معروفة؛ ما زالت مراجعة أدوات التطوير وإلغاء الجلسات عند تغيير كلمة المرور مطلوبة.
5. تحديد الأرصدة الافتتاحية الصحيحة للحسابات القديمة غير المهيأة من مصدر موثوق، دون التخمين.

## النشر

يمكن نشر تطبيق Next.js على Vercel أو أي بيئة تدعم Node.js. قبل النشر:

1. أضف متغيرات البيئة نفسها إلى إعدادات بيئة الإنتاج.
2. نفّذ `npm test` و`npm run test:db` و`npm run lint` و`npm run build`.
3. اتبع [تسلسل الترحيل والنشر](docs/data-isolation.md)؛ الكود الجديد يتطلب الـ View والـ RPC الجديدين.
4. أنشئ مستخدم Admin بطريقة آمنة، ولا تعتمد على إدخال دور Admin من واجهة عامة.
5. اختبر عزل البيانات باستخدام حسابين مختلفين.
